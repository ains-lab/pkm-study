# CTI-Thinker 논문 요약과 CAG 설계 시사점

## 질의

CTI-Thinker는 비정형 사이버 위협 인텔리전스에서 어떤 방식으로 지식 그래프를 만들고 공격을 추론하며, 그 결과를 CTI 기반 Agentic GraphRAG(CAG) 설계에 어디까지 재사용할 수 있는가?

## 한 문장 결론

CTI-Thinker는 **비정형 CTI → 엔티티·관계 추출 → 이명·표현 정렬 → ATT&CK 결합 그래프 → GraphRAG 질의응답**을 하나의 파이프라인으로 묶어 추출 성능을 높였지만, 소규모 질의 평가와 실제 로그·멀웨어 통합 부재 때문에 에이전트의 운영 판단 능력까지 입증한 연구로 확대 해석해서는 안 된다.

## 연구 문제

기존 CTI 처리에는 네 가지 병목이 있다.

- 보고서가 비정형이고 지식이 여러 문서와 문단에 파편화되어 있다.
- 엔티티·관계 주석이 전문가 노동에 크게 의존한다.
- APT 별칭과 같은 다의어·이형 표현이 그래프 중복과 잘못된 병합을 만든다.
- 일반 LLM과 텍스트 RAG는 ATT&CK의 전술·기법 구조 없이 공격 체인을 일관되게 추론하기 어렵다.

논문은 이를 단일 추출 모델의 개선 문제가 아니라 [[cyber-threat-intelligence-knowledge-graphs]]의 구축과 검색·추론을 잇는 종단 간 문제로 정의한다.

## 시스템 구조

| 단계 | 입력과 처리 | 산출물·역할 |
|---|---|---|
| 데이터 전처리 | 벤더 APT 보고서, 취약점 경고와 공개 CTI를 수집하고 LLM이 구조화 예시를 생성한 뒤 전문가가 검수 | instruction tuning과 ICL에 사용할 주석 데이터 |
| 엔티티·관계 추출 | LoRA로 조정한 LLaMA3-8B와 KNN 기반 ICL이 유사 예시를 prompt에 넣어 트리플을 생성 | 공격자, 도구, 취약점, 기법과 그 관계 |
| 지식 정렬·집계 | 의미 그룹화 후 SecureBERT 표현과 벡터 유사도로 별칭·동의 표현을 정렬 | 중복을 줄인 CTI 지식 그래프와 InfoBox |
| RAG 기반 공격 추론 | 질의를 그래프 커뮤니티에 투영하고 관련 노드·인접 관계·커뮤니티 요약을 회수한 뒤 ATT&CK/STIX 문맥과 함께 생성 | APT 표적, 도구, TTP와 공격 단계에 대한 답변 |

ICL은 현재 문장과 의미적으로 가까운 시범 예시를 선택하고, LoRA는 적은 학습 파라미터로 보안 도메인에 적응한다. 두 단계 정렬은 `APT32`와 `OceanLotus`처럼 표면형이 다른 동일 개체를 합친다. GraphRAG는 텍스트 조각만 이어 붙이지 않고 엔티티와 관계로 제한된 서브그래프를 prompt에 제공해 ATT&CK 기법까지 연결한다.

## 데이터와 정량 결과

CTI-Thinker 데이터셋은 학습·검증·시험 문장 2,762/345/345개, 엔티티 6,786/816/827개, 관계 3,957/477/509개로 구성된다. 데이터는 FireEye, McAfee, Kaspersky, MITRE, Qihoo 360 등의 APT 보고서와 공개 CTI 저장소에서 수집되었고, 추출 실험 결과는 10회 독립 실행 평균으로 보고되었다.

| 평가 | CTI-Thinker | 주요 비교 결과 | 해석 |
|---|---:|---:|---|
| 엔티티 추출 F1 | **0.8385** | LLM-TIKG 0.8004, ChatGPT-4o 0.7172 | 비교군 중 최고 |
| 관계 추출 F1 | **0.7689** | LLM-TIKG 0.6693, ATTCKG+ 0.5563 | 관계 추출에서도 최고 |
| 트리플 정렬 F1 | **0.7349** | 세 baseline 대비 평균 5.81% 향상 | 이형 관계 통합 효과 |
| 엔티티 정렬 F1 | **0.8288** | 세 baseline 대비 평균 5.50% 향상 | 별칭·동의 표현 정규화 효과 |
| 공격 추론 정확도 | **0.635** | LLM-RAG 0.615, Native LLM 0.223 | GraphRAG가 일반 LLM보다 크게 높지만 LLM-RAG 대비 절대 차이는 0.020 |

ICL 실험에서 KNN 예시 7개는 트리플 F1 0.7689와 엔티티 F1 0.8385로 결합 성능의 선택점이었다. 다만 엔티티 F1만 보면 예시 9개의 0.8528이 더 높다. 따라서 “k=7이 모든 지표에서 최고”가 아니라, 관계 추출과 엔티티 추출 사이의 실험적 절충으로 읽어야 한다.

## 공격 추론 평가

저자들은 20개 APT 조직을 대상으로 표적, 지역, 도구와 TTP를 묻는 30개 질의를 만들고, 온톨로지·별칭 정규화 후 exact-match accuracy를 측정했다. CTI-Thinker는 0.635로 LLM-RAG의 0.615와 Native LLM의 0.223을 앞섰다.

APT38 사례에서 시스템은 금융 부문을 주 표적으로 찾고 통신·정부·방산으로 확장했으며, Hermes·KEYLIME·DEYPACK을 T1059·T1566·T1055 같은 ATT&CK 기법과 연결했다. 이 사례는 구조화된 검색이 답변 범위를 좁히고 근거 관계를 제시하는 방식을 보여주지만, 30개 질의만으로 다양한 신규 공격 상황의 일반화를 입증하지는 않는다.

## 기여와 증거 수준

논문의 실질적 기여는 다음 세 가지다.

1. ICL과 LoRA를 결합해 엔티티·관계 추출부터 공격 추론까지 이어지는 통합 파이프라인을 제시했다.
2. 의미 그룹화와 벡터 정렬을 결합해 여러 CTI 출처의 별칭과 표현 변형을 정규화했다.
3. ATT&CK과 CTI 그래프를 함께 검색하는 GraphRAG 질의응답을 추출·정렬 실험과 분리해 평가했다.

반면 “자동 구축”은 완전 무인 자동화를 뜻하지 않는다. 전처리 단계에 LLM 생성 결과의 전문가 검수와 정제가 포함된다. 또한 논문은 서론에서 데이터셋 공개를 기여로 내세우지만 availability 문구는 데이터를 요청 시 제공하고 코드는 논문 수락 후 공개한다고 적는다. 이 요약은 현재 공개·재현 가능 상태를 별도로 확정하지 않는다.

## 한계

### 저자가 명시한 한계

- 중복 표현, 이질적 출처와 의미 모호성이 큰 공격 문맥에서는 semantic drift, 중복 트리플, 잘못된 병합·누락이 생길 수 있다.
- 인과 추적이나 전술 전환을 묻는 multi-turn reasoning에서 문맥 유지가 불안정하다.
- 추론 경로의 해석 가능성과 일관성이 실제 배포 수준에 이르지 못했다.
- 멀웨어 샘플과 이벤트 로그 같은 실제 위협 artifact를 통합하지 않아 사건 수준 추론과 귀속이 제한된다.

### 평가 설계에서 도출되는 주의점

- 공격 추론은 30개 질의·20개 APT 조직에 한정되고 LLM-RAG 대비 향상은 0.020이므로, 통계적 유의성이나 운영 효과를 단정할 근거가 부족하다.
- exact-match accuracy는 답변의 근거 충실도, 부분 정답, 최신성, 분석가가 검토할 수 있는 추론 경로 품질을 충분히 측정하지 못한다.
- 학습 자료와 평가 자료의 시간 분리, 신규 APT·미등록 ATT&CK 기법에 대한 out-of-distribution 시험이 보고되지 않았다.
- 추출 오류가 정렬과 GraphRAG를 거쳐 하류 판단으로 전파될 수 있지만 종단 간 오류 예산과 중단 기준은 제시되지 않았다.

## CAG 설계에 재사용할 것

- **단계 분리:** 추출, 정렬, 그래프 편입, 검색, 생성과 행동을 각각 검증 가능한 관문으로 둔다.
- **엔티티 해소 우선:** 별칭 정렬을 GraphRAG 이전에 수행하고, 자동 병합은 신뢰도·근거와 함께 저장한다.
- **ATT&CK을 의미 기준으로 사용:** 문서 유사도만이 아니라 전술–기법–절차 경로를 검색 단위로 삼는다.
- **그래프 근거 묶음:** 답변마다 회수한 노드, 관계, 원문과 ATT&CK 항목을 함께 제시해 분석가가 역추적하게 한다.
- **평가 층 분리:** 추출 F1, 정렬 F1, 검색 recall, 답변 정확도, 최종 대응의 안전성을 서로 다른 시험으로 측정한다.
- **운영 관문 결합:** [[autonomous-cyber-defense-agents]]가 이 지식을 행동에 사용할 때는 권한 제한, 최신성 확인, 사람 승인과 사후 검증을 추가한다.

## 그대로 일반화하면 안 되는 것

- CTI 추출 F1이 높다는 사실은 신규 조직의 실제 로그에서 공격을 잘 탐지하거나 올바른 대응 행동을 고른다는 증거가 아니다.
- ATT&CK 정렬은 알려진 기법을 표준화하는 데 유용하지만, 관측되지 않은 사건을 사실로 만드는 검증 장치는 아니다.
- CTI-Thinker는 지식 구축·질의 시스템이지 계획·도구 실행·복구 책임을 갖는 완전한 agentic architecture가 아니다.
- GraphRAG 답변을 곧바로 자동 대응으로 연결하지 말고, 원문 provenance와 시점, 충돌, 추출 신뢰도를 검사하는 별도 정책 계층을 둬야 한다.
